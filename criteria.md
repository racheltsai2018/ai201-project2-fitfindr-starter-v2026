# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
The criteria selected 4 out of 5 because the parsed parameters generated by the model can sometimes make mistakes. However, the majority of the time, it should stil be reliable. 

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
Following one of the branch rule, if 'search_listings' returns an empty list, a message will be put in the session and stop. Next, it will move on to the 'suggest_outfit' method.

---

## 3. Something about state

Given the listing returned from 'search_listings' and saved in session["search_results"], the listing returned will have the same id, title, and description as the new_item input into 'suggest_outfit'. The id, title, and description should be matching 5 out of 5 tries.


**Why this target:**
To ensure that the listing returned from 'search_listing' and entered into 'suggest_outfit' is the same item, the information for the item needs to be matching. For it to be 100% reliable, the information need to be matching 5 out of 5 tries.

Input a valid outfit and matching item from 'search_listing' and 'suggest_outfit' into 'create_fit_card', the returned caption should be under 280 characters and include both the suggested outfit and the new item in the caption in at least 4 out of 5 tries.

**Why this target:**
The reason 280 characters is selected as the limit because in the description it was mentioned that the generated caption should be able to be posted as a social media post. Most social media post are about 1-3 sentences. Occasionally, there would be post with longer caption but X put the post limit at 280 characters. The reason for 4 out of 5 tries is because the results generated from the model may include mistakes like going over the character limit or confusing the item with something else, or making a mistake when putting a description for the outfit.
